# 凭证与密钥轮换

## 生命周期

API Credential 创建后应设置过期时间和最小 Scope。凭证只在创建时显示一次明文，后续页面和审计记录只展示前缀与哈希指纹。

## 轮换流程

轮换时先创建新凭证并在灰度环境验证，再切换生产调用方，最后撤销旧凭证。两把凭证的重叠窗口应有明确截止时间，不能无限期保留。

## 泄露处置

怀疑泄露时立即撤销凭证、冻结异常主体、保留 trace_id，并检查过去 24 小时的调用日志。不要要求用户把密钥粘贴到聊天窗口，也不要把密钥放进 Prompt。

## 权限审计

每次创建、轮换、降权和撤销都写入审计事件。审计事件保留操作者、租户、credential_id、Scope 变化、结果和时间戳，不记录 Secret 原文。
