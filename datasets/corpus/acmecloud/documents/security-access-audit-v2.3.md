# 安全访问与审计

## 身份验证

管理员账号必须启用多因素认证（MFA）。推荐使用 TOTP 或企业身份提供商的强认证方式；短信验证码只作为临时恢复手段，不能作为长期管理员登录方式。

## 最小权限

成员默认使用 Viewer 角色。只有确需管理知识库、配置应用或处理工单的人员才授予 Admin。跨租户访问必须通过单独的应用绑定和服务端策略，不能通过前端参数放宽范围。

## 审计留痕

登录、权限变更、知识库导入、索引发布、工单确认和凭证撤销都会写入审计事件。审计事件至少保留操作者、租户、资源、动作、结果和时间戳；Token、密码和完整文档正文不得写入日志。

## 发现异常

发现异常登录或权限提升时，应先撤销相关 Credential，再冻结账号并保留 Trace ID。任何安全事件都不能要求用户在聊天中提交密码或 API Key。
